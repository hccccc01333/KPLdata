## 1. 产品定位

**一句话**：以 10 名选手为卡片矩阵，实时/复盘展示 KDA、经济、输出承伤、参团、出装与铭文，服务教练盯人与分析师做分路拆解。

**目标用户**

| 角色 | 核心诉求 |
|------|----------|
| 教练组 | 看对位经济、出装节奏、谁在打出伤害/承伤 |
| 数据分析师 | 出装路径聚类、铭文分布、参团与经济效率 |
| KPI / 运营 | 选手高光卡片、MVP 叙事 |

---

## 2. 用户故事（含验收标准）

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-01 | 作为教练，我要按分路对比双方选手 | 5 行对位布局；显示英雄、选手名、KDA、经济、等级 |
| US-02 | 作为教练，我要点开选手看出装 6 槽 | `BriefEquipList` 图标/名称；缺失标「—」 |
| US-03 | 作为分析师，我要看铭文 | `symbol_ids` → 名称字典；无字典时显示 ID 并标「待映射」 |
| US-04 | 作为教练，我要看输出/承伤占比与参团率 | `hurt_*_rate` / `participation_rate`；环比对位 |
| US-05 | 作为分析师，我要看经济效率 | 伤害/经济、承伤/经济；与同位置赛段分位（待建） |
| US-06 | 作为运营，我要高亮 MVP / 败方 MVP | `is_mvp` / `is_lose_mvp` |
| US-07 | 作为教练，赛中面板随快照更新 | 绑定同一 `battle_id` 最新 snap；刷新同 P02 |
| US-08 | 作为分析师，我要导出 10 人宽表 | CSV 含身份+战绩+装备 ID 列表 |

## 3. 信息架构 & UI

### 3.1 页面区块

1. **局头**：对阵、分钟、比分经济摘要  
2. **对位矩阵（主）**：左蓝右红，五行分路  
3. **选中选手抽屉**：出装、铭文、技能简况、趋势 sparkline（经济）  
4. **队内占比条**：输出/承伤/经济份额  
5. **底栏**：召唤师技能；MVP 标记  

### 3.2 Mermaid 线框

```mermaid
flowchart TB
  Head[局头·时间/总经济/击杀]
  subgraph Matrix [对位矩阵 5x2]
    Top[对抗路 蓝卡 | 红卡]
    Jug[打野]
    Mid[中路]
    ADC[发育路]
    Sup[游走]
  end
  Drawer[选手抽屉·出装6槽/铭文/技能]
  Bars[队内输出承伤经济占比]
  Head --> Matrix
  Matrix -->|点击卡片| Drawer
  Matrix --> Bars
```

### 3.3 状态设计

| 状态 | 表现 |
|------|------|
| 无 players | 空态：快照无 `battle_player_list` |
| 装备空（赛初） | 槽位虚线框「未出件」 |
| 铭文未映射 | 显示 raw ID + 警告标签「估算词典缺失」 |
| 加载 | 10 卡片 skeleton |

## 4. 关键指标与统计方法

| 指标 | 定义 | 窗口 | 公式 / 方法 | 置信/显著性 |
|------|------|------|-------------|-------------|
| 对位经济差 | 同分路 c1−c2 gold | 当前 | 与 `c1_gold_{pos}` 同源 | — |
| 参团率 | 官方字段 | 当前/终局 | `participation_rate`（%） | 官方口径标签 |
| 输出占比 | 对英雄伤害队内比 | 当前 | `hurt_to_hero_total_rate` | 官方 |
| 经济效率 | 对英雄伤害 / gold | 当前 | \(hurt/gold\) | 赛段分位 + 95% 分位带（待建） |
| 出装相似度 | 与赛段同英雄高频出装 Jaccard | 终局 | 集合相似度 | Bootstrap CI（待建） |
| MVP 分 | 官方评分 | 终局 | `mvp_score` | 官方 |

**教练口径**：赛中出装以「可见快照」为准；未刷新到的槽位不得脑补。铭文无官方中文名时不得假装已解析。

## 5. 数据源

| 技能 | `BriefHeroSkillList` / 召唤师技能 | 辅 | **字段已有 · UI 待建** |
| Dashboard | 无选手出装页 | — | **待建** |
| 辅源 | 装备/铭文静态表（营地或社区整理） | ID→名 | **待建** |

## 7. 与竞品差异

| 维度 | 对齐 | 本产品更深 |
|------|------|------------|
| 选手数据卡 | 营地/数据站 | 与 **分路特征、胜率时间轴** 同屏深链 |
| 出装 | 常见 | 出装路径 + 赛段分位 + 置信 |
| 铭文 | 常缺失或不透明 | **显式映射状态**；无字典不装有 |

## 8. 实现优先级

| 优先级 | 能力 | 依赖现有代码 |
|--------|------|----------------|
| **P0** | 对位矩阵：英雄/KDA/经济/等级/参团 | `snap["players"]`；POSITIONS |
| **P0** | 出装 6 槽展示（有 ID/图标即显示） | `BriefEquipList` |
| **P1** | 铭文字典与映射状态机 | 静态表建设 |
| **P1** | 经济 sparkline、效率分位 | 快照序列 |
| **P2** | 出装路径挖掘、导出、P09 联动 | 批处理 |

### 已有 vs 待建

| 已有 | 待建 |
|------|------|
| raw 含选手完整字段；`parse_snapshot` 保留 `players` 并做分路聚合 | 面板 UI、装备/铭文渲染、字典、分位、导出 |
| FeatureBuilder 分路 gold/hurt/level 差 | 单兵出装未进模型（有意） |

## 9. 验收清单

**数据正确性**

- [ ] 10 人身份与 camp/position 正确  
- [ ] 装备列表长度 ≤6 且与 raw 一致  
- [ ] 铭文映射失败时降级策略可测  

**性能**

- [ ] 随 P02 5s 刷新不卡顿；重渲染可增量  

**视觉**

- [ ] 对位对齐；MVP 高亮不遮数据  
- [ ] 来源标签：官方字段 / 字典映射 / 估算分位
