## 2. 矩阵 B · 新 IA：六个顶层入口 → 页面映射

原则：**能力在增长，入口不增长**。用户只看到 6 个顶层入口，复杂筛选藏在页内。

| 顶层入口 | 承载页面 | 与现状差异 |
|---|---|---|
| **赛事** | `index.html` · `schedule.html` · `match.html` · `game.html` · `picks.html` | 首页与赛事中心合并为一条"今日 → 直播 → 赛果 → 复盘"路径 |
| **战队** | `teams.html`（战力榜） · `team.html`（详情） · `h2h.html` · 对比-战队 | 新增战力分与能力雷达；冠军墙有逻辑 |
| **选手** | `players.html` · `player.html` · 对比-选手/位置 · **荣誉中心** | 新增筛选体系、同位置均值线、周月荣誉 |
| **英雄** | `heroes.html` · `hero.html` · `combos.html` · 对比-英雄 | 新增分路库、对位、成长曲线、组合三层 |
| **分析** | `bp.html` · 赛段对比 · 比赛转折 · 翻盘路径 · `simulator.html` | 对比工具拆分后归入此处；转折/翻盘为新建 |
| **荣誉** | 荣誉中心（周/月/年度） · 分享图 | **全新入口**（自动内容生产系统） |

> 首页首屏只突出**正在发生的比赛**与**本期最重要的数据结果**，点任一卡片直达分析内容，不经过多层筛选页。

## 4. 矩阵 D · 视觉规范要点

| Token | 值 | 用途 |
|---|---|---|
| 背景 | 深黑 / 炭黑 | 页面底 |
| 卡片 | 深灰 | 面板 |
| 主文字 | 白 | 正文、数字 |
| 次文字 | 灰 | 说明 |
| 蓝方 | 冷蓝 | camp1 / 一方 |
| 红方 | 暖红 | camp2 / 另一方 |
| 强调 | 金 / 电光青 | 胜率、关键结论 |
| 警示 | 橙 | 风险、样本不足 |

原则：**信息优先、少装饰、少无意义发光、少堆叠边框**；中文用清晰无衬线体，数字用等宽/表格数字；视觉重点让给胜率、比分、排名与结论。
参考官方（BP 板、对比图、能力图、金币趋势）但**目标是"官方赛事视觉感 + 专业分析终端能力"，功能深度超过官方**，不做成"像官网专题页"。

## 5. 前置阻塞与明确不做

**B1 · 分路映射（阻塞全部同位置类分析与复盘曲线）**
五人序列按姓名排序取前 5 → 必须先建 `position_ordinal`（对抗路→打野→中路→发育路→游走）并对齐，再谈任何"同位置"结论。

**B2 · 分钟级覆盖边界**
可用分钟序列 **221 局 / 全量 11,126 局 ≈ 2.0%**。所有时序类功能（成长曲线、战术 DNA、转折、翻盘）**必须标注覆盖范围**，禁止缺失填充。

**本轮不做**：
- 不新建统一事实表（Phase 1 规格已按用户决定搁置，§9 的 5 个未决问题待评审）
- 不先修"看起来是 P0 但实测不存在"的三项
- 不在首页重做之前单独给赛果卡加赛段标签（见 §0 P1-2：改动横跨 `build_data.py` 数据管道 + `common.js` 渲染两层，而首页赛果区本就要重做 —— 改两遍是浪费）

## 6. 建议推进顺序（收敛，不承诺范围）

| 阶段 | 内容 | 可验收成果 |
|---|---|---|
| 0 | 已确认缺陷：两张入口卡图标（**已完成**）、P1-2 赛段/赛制标签归入首页重做 | 全站验收 exit=0 |
| 1 | **首页 + 赛事中心重做** | 首页按比赛日组织；赛事中心含直播海报与赛段进程 |
| 2 | **荣誉中心一期** | 选定一个已完赛自然周，产出五路候选 + 公式 + 不确定性（可复算） |
| 3 | **战队体系重做**（战力榜 + 详情三层） | 冠军墙有逻辑；雷达三种基准可比 |
| 4 | **分析工具重做**（BP 双模式、对比拆分、模拟器升级） | 推荐可解释、概率可校验 |
| 5 | 视觉收尾 + 分享图 + 部署验收 | 手机可用、少跳转、图片可传播 |

> B1 应放在阶段 0/1 之间完成（它是阶段 3–5 多条功能的共同前提）。
