### 2.4 模型可信度（对应"预测模型不要只追准确率"）

现状：`train_realtime_model_v9.py` 训模型、`backtest_realtime_v9.py` 出 holdout 报告（`data/realtime/backtest_v9_report.json`），站点 `predict.html` 展示分阶段准确率 + Brier。**缺口**：训练/校准/测试切分没有在代码里硬隔离（同一批最近比赛既用于选模型又用于报告），"终局前预测 100% 命中"这类口径也不能当作模型能力。

后续动作：
1. 增加 `split.py`：按**时间**切 train / calibrate / test，模型选择只看 calibrate，test 只跑一次；
2. `predict.html` 的"直播预测档案"标注每个样本的预测时点（如 "12′"），并增加固定节点（8′/12′/16′）命中率，替代最后一帧口径；
3. 报告写入 `docs/model-card.md`（数据范围、口径、已知偏差、不可用场景）。

## 五、风险与数据边界

1. **版本对比**：`data/history` 里没有可靠的补丁/版本号元数据，先做"赛事/年份/赛段"对比；版本维度需要补腾讯侧版本字段或人工维护补丁表。
2. **因果 vs 相关**：事件归因只能给"时间邻接 + 指标同向变化"的证据摘要，页面文案不得写成因果结论（`replay` 的 cards 需统一措辞）。
3. **样本门槛**：所有胜率类展示需同时给 n 与置信区间（已有 `ciLo/ciHi` 的部分页面要推广到全部排行）。
4. **双前端收敛**：site 是唯一对外产品；Dashboard 只保留内部视角（数据健康、模型调试、批量校验），新分析能力先落 site。

## 七、阶段三进展（分析体系重构）

### 7.1 BP 对阵假设工作台（bp.html 顶部新增，原八维浏览保留在下方）

**交互**：选数据范围 → 选 A/B 战队 → 假设双方各 2 个关键英雄 + 各 1 个对敌禁用 → **即时给出胜率与替代方案**。

**模型（写在页面上，可复核）**：

```
base  = logit(wrA) - logit(wrB)
edge_T(h) = logit((w + k*prior)/(n + k)) - logit(wr_T)     k = 25（先验收缩）
dLogit = 0.9*sum(pick_edge) - 1.1*sum(ban_edge*max(0.35, usage))
P = sigmoid(base + dLogit)
```

页面同时输出：赛前基准 / 调整后概率 / 变化 pp、每条假设的贡献表、双方替代方案（样本>=5 局，按边际排序）。

**诚实性**：底部固定声明「未考虑版本、阵容联动与对手反制，不等于因果结论」；权重与 k 全部明文写在页脚，便于质疑与调参。

**验证**：Node + DOM 桩渲染真实数据（默认 A=重庆狼队 vs B=北京WB）：基准 52.5%、替代方案给出「鲁班大师 178 局 65.2% +5.8pp / 沈梦溪 232 局 62.5% +3.3pp …」。

### 7.2 选手详情统一（player.html）

- **同位置对比**（新增）：与同位置 >=20 局的选手比 5 项指标（胜率 / KDA / MVP 率 / 参团 / 输出），给出百分位、位置中位与「超过 X%」，并声明「不做跨位置比较」；
- **逐年明细**（新增）：在原有胜率折线之外补局数与 KDA，避免「只看一条线」；
- 验证：`player.html?id=清清` 实测 → 对抗路 19 人对照，胜率 57.1% vs 位置中位 51.7%（超过 84%）。

### 7.3 对比工具整合（compare.html）

- 5 个 tab 收敛成 **3 个对象类型（英雄 / 选手 / 战队）+ 1 个「趋势视图」开关**，内部复用原有渲染层；
- **差值突出**：选 2 个对象时多一列「差（1-2）」，正负分色，自动剥离指标自带符号（修掉 `-+233` 这类显示错位）；
- **可达性**：表头对象名直达 hero/player/team 详情页；

### 7.4 阶段三遗留

1. 「模型」徽标目前恒等于「分钟级」（有重放包才有概率），建议合并为一枚或接入直播预测存档拆分；

### 9.4 精选对局索引（picks.html，阶段四最后一项）

**做法**：`build_picks.py` 读取 `assets/replay/*.json` 的逐帧数据，按 4 条可复核规则打标签，输出 `assets/picks.js`（18KB，48 条）。

| 标签 | 规则（页面同步展示） | 入选 |
|---|---|---|
| 翻盘局 | 第 6 分钟之后、经济落后 ≥3,000 时，收官胜方胜率仍 ≤10% | 8 |
| 拉锯局 | 时长 ≥20 分钟 | 16 |
| 波动局 | 任意 3 个采样点内胜率变化 ≥55pp | 39 |
| 资源战 | 结构性事件（推塔/暴君/主宰/风暴）≥16 个 | 18 |

阈值不是拍脑袋：先跑 202 局的分位数（minProb p25≈0.16、swing3 p75≈0.54、时长 p75≈17.7、事件 p75≈14），再取更严的档位，避免「人人都精选」。

**关键设计**：卡片上的「翻盘局」必须同时满足**时间够晚 + 经济真的落后**——早期低置信采样（第 2 分钟胜率 2% 但金差只有 +225）不算翻盘；这条修完之后翻盘局从 42 条收敛到 8 条，每条都能在复盘页核对到具体分钟与金差。

**联动**：每张卡片的链接是 `match.html?id=&g=&m=`，点进去**直接落到关键分钟**（复用阶段四的分享深链），首页「精选复盘」的『更多精选』也指向这里。
